# 产品下一步计划

> 更新日期：2026-09-30  
> 定位：MeridianOps 做 **混合运维控制面**（资产/服务、告警处置、变更与工具入口），不做云原生可观测数据面，不自建全量采集/Discovery 引擎。  
> 总路线仍见根目录 [README.md](../README.md) 开发路线图；本文是 **近期可执行切片**。

## 原则

| 做 | 不做（近期） |
|----|----------------|
| Eventide 汇聚告警 + 关联 CI/服务 | 直连各云监控做第二套告警中心 |
| CMDB 抽象模型 + 同步适配器 + 对账 | 自建全网 Discovery / 泛采集平台 |
| 运维工具外链（及后续 SSO） | 门户 iframe 复刻 Zabbix/云控制台 |
| 传统 SSH 作业保留，预留云侧变更 | 把「监控纳管」做成小 Zabbix |

相关文档：

- [运维工具 SSO 计划](./ops-tools-sso-plan.md)
- [Zabbix 纳管设计](./zabbix-control-design.md)（能力保留；产品优先级低于控制面主线）

---

## Now（约 1～2 周）— 演示面收口

- [ ] 空壳菜单隐藏或标「规划中」：`/containers`、`/database`、`/config`、`/cost`
- [ ] 「运维工具」配置真实外链（Zabbix / Grafana / 云监控等），去掉占位域名
- [ ] 「监控纳管」降噪：模板偏离默认关或移出首屏；队列/Proxy 收入可折叠「平台健康」
- [ ] （可选）监控纳管菜单降级说明或与运维工具分工文案

验收：侧栏无空壳误导；运维工具点开能进真实系统；纳管页不再用大红「偏离」吓人。

---

## Next（约 2～4 周）— CMDB 服务化 / 云抽象

- [ ] 新增或扩展 CI 模型：`service`（或应用）挂在业务系统下
- [ ] 云公共字段约定：`provider`、`region`、`external_id`、`cloud_account`（可落在 host/database 扩展属性或独立抽象模型）
- [ ] 按需增加轻量模型：`cloud_rdb` / `cloud_lb` / `cloud_object_storage` / `vpc`（或统一 `cloud_resource` + `resource_type`）
- [ ] 告警/拓扑优先展示「服务」关联，主机为下层

验收：能录入/同步「业务系统 → 服务 → 运行实例」；华为云与紫光云可用同一套抽象 + 扩展 JSON 区分。

---

## Later（约 4～8 周）— 同步与变更通道

- [ ] 落地 **1 个** 云同步适配器（华为云或紫光云二选一）+ 对账（源有库无 / 库有源无）
- [ ] 作业：SSH 维持；预留云 API / 外部自动化（理想等）触发接口
- [ ] 运维工具 SSO（见 [ops-tools-sso-plan.md](./ops-tools-sso-plan.md)）
- [ ] 态势中心接真实数据；全局搜索 MVP（与 README「下一轮产品 P0」对齐）

验收：至少一条云资源链路可定时入库并对账；外链仍可用，SSO 有设计可试点。

---

## 明确不排期（除非需求变更）

- 自建全量资源采集 / 网段 Discovery 平台
- 门户内复刻 Prometheus / 链路追踪 / 云监控大盘
- 多云一次做齐（先一家适配器跑通）
